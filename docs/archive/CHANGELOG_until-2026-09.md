# Changelog

> **Dokumen riwayat.** Changelog lama sampai 2026-09-11. Changelog yang dipelihara ada di `logs/CHANGELOG.md`. Keadaan sekarang (Room schema 11): `README.md`, `docs/DOMAIN_MODEL.md`, `docs/V1_IMPLEMENTATION_SPEC.md`, `docs/diagrams/`, dan keputusan di `logs/DECISION_LOG.md`.

## Unreleased

### Added

- A standardised MSME feasibility workbook, `simulasi_kelayakan_umkm_verifikasi.xlsx`, generated by
  `scripts/generate_verification_workbook.py`: a three-month bottled-sambal case study across five
  coordinated sheets whose derived figures are live Excel formulas carrying the exact cached values
  the Kotlin domain computes. `VerificationWorkbookTest` imports it through the real importer and
  reconciles 26 figures to the rupiah; it fails hard rather than skipping if the file is missing.
- A daily ledger may declare each row's kind in a `Jenis` column, giving imports the full event
  vocabulary — capital, loans, credit sales, settlements, principal, interest, equipment (D-052).
  The shipped MSME template uses it, so a template's own "Setoran Modal Awal" is no longer imported
  as sales revenue.
- Volume, unit and unit price now survive an import instead of being retyped by hand.
- `BudgetPlanCalculator`: a projection book holding only a RAB reports from that RAB, and the card
  says so, instead of showing Rp0 for cost, break-even and B/C ratio (D-054).
- `FeasibilityCard`: break-even and B/C ratio as meters with a Layak / Waspada / Tidak Layak status,
  shared by Beranda and Laporan (D-057).
- `RecordSpeedDial`: Catat Pemasukan and Catat Pengeluaran in the bottom-right thumb zone, opening
  the entry form directly on that kind.
- A "Belum Lunas" quick filter on the ledger, and a Pilih Berkas → Tinjau → Simpan step indicator on
  the import card.
- Planning parameters — capacity, selling price, capital, loan, interest, financing cost, opening
  cash — are read from a workbook's parameter sheet into the projection book's Asumsi, with a
  provenance record and a visible notice, instead of being retyped by hand (D-058).
- RAB lines carry the month they are planned for, so a projection book produces a real cash schedule
  and a real working-capital figure. The case study reports Rp14.850.000 where it used to report
  Rp0 (D-059).
- The business sector picker is back in the create-business sheet; the four templates from D-048
  had been unreachable (D-061).

### Fixed

- A five-view workbook's RAB could be dropped into the realization book, leaving the plan empty,
  because the target-book picker applied one choice to every row (D-053).
- RAB volumes were stored as `"6000.0"` on the five-view import path.
- "Kas setelah pembiayaan" double-counted realized capital and loans on the realization book; the
  assumption card is now projection-only (D-055).
- Break-even and margin figures rendered as `4673.214` and `22.11`; they now group and separate the
  Indonesian way, like every other number in the app.
- Ampersands had returned to `BusinessTemplate` and 30 strings; swept again, and the sector name
  "Kuliner / F&B" became "Kuliner dan Makanan Olahan".
- Every category an import invented was created as an operating expense, so on any workbook whose
  names did not match the business template a revenue target and an equipment budget both counted
  as cost (D-060).
- "Total RAB" summed revenue targets into planned cost, making the Realisasi vs Target comparison
  meaningless.
- The speed dial covered the last card on Beranda and Catatan.
- `gradlew test` failed outright on a Windows machine whose `Path` holds a quoted path list; the
  build now strips those quotes for the test worker (D-062).

### Added (earlier)

- Native Kotlin/Jetpack Compose Android app with adaptive phone/tablet navigation.
- Room schema for businesses, projects, financial events, balanced journals, postings, budgets,
  obligations, settlements, import batches, provenance, and notices.
- Local multi-business and multi-project workflows. Nothing is created on the user's behalf: a first
  run legitimately has no scope and offers explicit "Tambah Usaha" / "Tambah Lahan" (D-015).
- Full create/select/edit/archive of usaha and lahan from a bottom sheet opened at the scope picker
  itself (D-024).
- Exact-rupiah transaction entry and derived profit, operating cash, financing cash, and cash
  balance. Money is stored as integer rupiah; no floating point anywhere on the money path.
- Budget (RAB) per book, receivables/payables with settlement, and plan-versus-actual comparison.
- Native OOXML workbook reader, import preview, deterministic enrichment with provenance, atomic
  commit, duplicate-hash guard, and full batch reversal.
- On-device categorisation of imported rows — keyword then fuzzy match, no model, no network — so an
  imported workbook arrives with a real cost breakdown rather than one bucket (D-034).
- Excel and PDF export, and encrypted `.aabk` backup/restore with a pre-restore recovery export.
- Indonesian and English throughout, including messages produced outside composition (D-021).
- Guided tour drawn as a real canvas cutout over the live UI.
- A Material 3 colour system generated from the brand green by Material Color Utilities, with the
  full role set for light and dark, money-specific roles harmonised toward the seed, and a
  categorical chart palette; 96 measured contrast pairs, all passing (D-028, D-029).
- A Gerakan setting that also honours the system animation scale (D-025).
- Golden integration tests against the verified facilitator workbook and a sanitized enrichment
  fixture, plus an end-to-end test that runs the real exporter and importer over the golden case.

### Changed

- Every modal in the app is one `MankeuSheet` bottom sheet; `AlertDialog` is no longer used (D-023).
- Sheets have a half-expanded snap point, actions that do not scroll away, and resize for the
  keyboard instead of hiding the field being typed into (D-031).
- Depth is carried by surface-container tones; drop shadows are light-mode only (D-030).
- Version string restarted at `0.0.1` and the term "SemVer" removed from user-facing text (D-016).

### Removed

- `saved_mappings` and the write-only `projects.status`, `templateKind` and `templateMetadata`
  columns. Database version 3 (D-026).
- The three disabled sign-in buttons on the account card; the notice explaining that sync is not
  built yet remains (D-027).

### Boundaries

- Package identity migrated to `com.mankeu`.
- Cloud sync, authentication, release signing, and Play publication are not implemented.
- Cloud sync is designed but not built: see `docs/CLOUD_SYNC_AND_AUTH.md` (D-033).
- Backups written before database version 3 cannot be restored by this build; the app is
  pre-release and uses a destructive migration fallback.
