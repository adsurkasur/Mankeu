## Daftar Temuan Bug & Jitter

### J-1: Bottom Sheet (`MankeuSheet`) Bergetar dan Melompat Saat Keyboard Muncul
- **Tingkat**: Berat
- **Layar**: Semua form/dialog yang menggunakan `MankeuSheet` (mis. sheet baris produk di nota, sheet satuan jual, catat stok bahan, dialog konfirmasi).
- **Langkah Reproduksi**:
  1. Buka Nota Penjualan baru (`SaleNoteEditorScreen`).
  2. Ketuk baris produk untuk membuka sheet edit produk (`SaleUnitSheet`).
  3. Ketuk field harga atau jumlah untuk memunculkan software keyboard.
- **Hasil**:
  Sheet melompat ke atas secara drastis, bergetar/memantul saat animasi keyboard berlangsung, dan padding navigasi bawah bertambah dua kali lipat.
- **Penyebab (Root Cause)**:
  1. `ModalBottomSheet` di Jetpack Compose Material 3 secara default telah menerapkan `contentWindowInsets` (`BottomSheetDefaults.windowInsets`).
  2. Di `MankeuSheet.kt:93-94`, kolom konten menerapkan `.imePadding()` dan `.navigationBarsPadding()`.
  3. `AndroidManifest.xml` menyetel `android:windowSoftInputMode="adjustResize"`.
  4. Ketika keyboard terbuka, Window Manager meresize window dialog DAN `imePadding()` menambahkan padding keyboard pada saat yang sama dengan kurva animasi yang berbeda. Terjadi double-insets dan bouncing.
- **Harapan**:
  Sheet naik secara halus mengikuti keyboard tanpa lompatan ganda atau getaran.
- **Rencana Perbaikan**:
  Gunakan penanganan insets terpadu pada `ModalBottomSheet` (`contentWindowInsets = { WindowInsets(0, 0, 0, 0) }` atau via `BottomSheetDefaults.windowInsets.union(WindowInsets.ime)`) dan hilangkan padding ganda `imePadding()` / `navigationBarsPadding()` yang bertabrakan.

### J-2: Bottom Bar Simpan pada Form Penuh (`FullPageForm`) Melompat ke Tengah Layar Saat Keyboard Muncul
- **Tingkat**: Berat
- **Layar**: Nota Penjualan, Belanja, Uang Masuk Lain, Uang Keluar Lain, Modal & Prive, Editor Produk.
- **Langkah Reproduksi**:
  1. Buka form Belanja atau Nota Penjualan.
  2. Ketuk input jumlah atau harga sehingga keyboard terbuka.
- **Hasil**:
  Tombol "Simpan" dan `ResultBar` melonjak jauh ke tengah layar di atas keyboard, lalu turun kembali dengan jitter.
- **Penyebab (Root Cause)**:
  `FullPageForm.kt:78` menerapkan `.windowInsetsPadding(WindowInsets.navigationBars.union(WindowInsets.ime))` pada `bottomBar` di dalam `Scaffold`.
  Karena `adjustResize` sudah mengecilkan ukuran `Scaffold` sesuai tinggi keyboard, penambahan `WindowInsets.ime` pada `bottomBar` menambahkan padding setinggi keyboard LAGI di dalam window yang sudah mengecil.
- **Harapan**:
  Tombol Simpan tetap tepat di atas keyboard secara stabil dan menempel di dasar layar saat keyboard tertutup.
- **Rencana Perbaikan**:
  Konsumsi insets secara tepat pada `Scaffold` (`contentWindowInsets = ScaffoldDefaults.contentWindowInsets`) dan selaraskan padding bottomBar agar tidak terjadi double-push keyboard.

### J-3: Tinggi `ResultBar` Berubah Mengakibatkan Lompatan Vertikal Form Penuh
- **Tingkat**: Sedang
- **Layar**: `SaleNoteEditorScreen`, `MoneyFormScreen`, `ProductEditorScreen`.
- **Langkah Reproduksi**:
  1. Buka form Belanja / Nota Penjualan.
  2. Ketik angka: saat total masih 0, `result` adalah `null` (tidak ada bar).
  3. Saat angka valid dimasukkan, `ResultBar` tiba-tiba muncul di `bottomBar`.
- **Hasil**:
  Tinggi `bottomBar` melompat dari ~56 dp menjadi ~110 dp. `Scaffold` merubah `paddingValues` untuk konten, mengakibatkan seluruh form terdorong atau melompat naik.
- **Penyebab (Root Cause)**:
  `result` dirender secara kondisional (`result?.invoke()`) tanpa ruang yang dicadangkan atau transisi tinggi yang halus.
- **Harapan**:
  Ruang untuk `ResultBar` dicadangkan atau terintegrasi secara stabil sehingga tinggi bottom bar tidak melompat.
- **Rencana Perbaikan**:
  Cadangkan tinggi minimum atau satukan layout info hasil di dalam bottom bar.

### J-4: Scroll Melompat dan Re-render Masif pada `LazyColumn` Tanpa Kunci (`key`)
- **Tingkat**: Sedang
- **Layar**: Beranda (`HomeScreen`), Tab Produk (`ProductsScreen`, `StockSection`), Daftar Catatan, Rencana Usaha (`PlanScreen`), `PickerPage`.
- **Langkah Reproduksi**:
  1. Scroll daftar di Beranda atau Produk.
  2. Saat ada item dinamis muncul (misal Tagihan pelanggan ada/tiada, peringatan stok menipis, atau filter diubah).
- **Hasil**:
  Posisi scroll melompat, item-item berkedip karena di-recompose dan re-layout secara keseluruhan.
- **Penyebab (Root Cause)**:
  - Di `HomeScreen.kt`: semua `item { ... }` (ProfitCard, CashOnHand, QuickActions, BillsCard, dsb.) tidak memakai parameter `key`.
  - Di `ProductsScreen.kt` & `StockSection.kt`: item header, ringkasan stok, dan tombol tambah tidak memiliki `key`.
  - Di `PickerPage.kt:81`: `items(shown)` tidak memiliki `key`.
- **Harapan**:
  Setiap item di `LazyColumn` memiliki identitas stabil (`key`), sehingga Compose dapat melacak posisi scroll dan hanya meng-update item yang benar-benar berubah.
- **Rencana Perbaikan**:
  Beri `key` eksplisit dan unik untuk setiap `item(key = "...")` dan `items(..., key = { ... })`.

### J-5: Perhitungan Berat `ProductCosting.cost` di Dalam Loop Komposisi UI
- **Tingkat**: Sedang
- **Layar**: `ProductsScreen`, `SaleNoteScreens`.
- **Langkah Reproduksi**:
  1. Scroll daftar produk dengan 5–10 produk dan resep.
- **Hasil**:
  Frame rate drop / jank frames tinggi (layar terasa berat dan tersendat).
- **Penyebab (Root Cause)**:
  `ProductCosting.cost(record.spec, prices)` dipanggil berulang kali di dalam lambda `items(products)` pada setiap frame scroll tanpa `remember`.
- **Harapan**:
  Perhitungan biaya/HPP hanya dijalankan ketika spesifikasi produk atau harga bahan berubah (`remember(record.spec, prices)`).
- **Rencana Perbaikan**:
  Bungkus komputasi dengan `remember(record.spec, prices)`.

### J-6: `animateContentSize` pada Kartu Besar di Dalam Kontainer Scroll
- **Tingkat**: Sedang
- **Layar**: `ReportsScreen` (`ExpenseDistributionCard`).
- **Langkah Reproduksi**:
  1. Buka Laporan, buka tab Distribusi Biaya / Donat.
  2. Data kategori dimuat.
- **Hasil**:
  Animasi ukuran kartu (`animateContentSize`) memicu relayout berkelanjutan pada LazyColumn selama durasi animasi, menyebabkan jitter pada konten di bawahnya.
- **Penyebab (Root Cause)**:
  `Card` memiliki `Modifier.fillMaxWidth().animateContentSize(...)` di dalam item scroll.
- **Harapan**:
  Layout kartu stabil tanpa animasi perubahan ukuran vertikal yang memaksa relayout scroll.
- **Rencana Perbaikan**:
  Hilangkan `animateContentSize` pada kartu di dalam scroll.
